# REVIEW.md

Every defect below was fixed in the rewrite of `app/main.py`. Each row gives a concrete failing input.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses `punch_in.replace(hour=...)` in the punch's own (server-local, naive) timezone instead of IST; compares floor-minutes `> 10` instead of seconds `> 600`; never truncates sub-seconds; ignores overnight shifts. | Shift 09:30, punch `09:40:00.900` IST → returns 10, must be 0 (truncate first: 09:40:00 is inside grace). Punch `09:40:01` → returns 0, must be 10. Punch `10:15:59` → returns 45 (correct by accident). On a non-IST server every value is shifted. | Convert punch to aware UTC, truncate to seconds, compare against the shift-start instant built in IST; `0` unless diff `> 600`s, else `floor(diff/60)`. Overnight handled via attendance-date shift start. |
| 2 | `compute_work_hours` | `round()` is banker's rounding on a binary float, spec requires half-up (R4). | 9630 s = 2.675 h: `round()` gives 2.67, must be 2.68. | `Decimal(seconds) / 3600` quantized to 0.01 with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | Missing the 30-minute minimum (returns any positive diff); builds shift end on the record's date even for overnight shifts (end lands 16 h early); mixes naive server-local `punch_out` with an IST-aware `end` (TypeError or wrong diff); no truncation. | Punch-out 5 min after shift end → returns 5, must be 0 (R3). Overnight 22:00–06:00, out 06:40 next day → negative diff → 0, must be 40. | Floor minutes from the true shift-end instant (next day when overnight), `0` when `< 1800` s; all datetimes aware UTC, truncated. |
| 4 | `health` | Never pings MongoDB; always 200 even with the database down. | Stop mongod → still 200, runner thinks the app is ready. | `db.command("ping")`, 200 `{"status":"ok"}` on success, 503 otherwise. |
| 5 | `create_employee` | Check-then-insert race: two concurrent duplicate `emp_code` both pass `find_one` → duplicate rows or 500 instead of exactly one 201 + 409s. Also: `datetime.now()` naive local (not UTC); returns `created_at` as ISO string, not epoch ms; no validation of `emp_code` pattern, email, `joined_on`, or `shift_start != shift_end`. | 8 parallel creates of `EMP0099` → >1 row. Response `created_at` is a string, contract wants int ms. `shift_start == shift_end` accepted. | Unique index on `emp_code` + catch `DuplicateKeyError` → 409; server UTC timestamp truncated to seconds; full Pydantic validation; serialize `created_at` to ms. |
| 6 | `list_employees` | `skip = page * page_size` (page 1 skips the first page); `total` counts the whole collection, ignoring `department`; no `emp_code` sort; no `page`/`page_size` validation; `created_at` not converted to ms. | With 4 employees, `page=1,page_size=2` returns employees 3–4. `?department=Sales` reports `total: 4`. `page=0` accepted. | `(page-1)*page_size`, filtered count, DB sort, `Query(ge=1)/(ge=1,le=100)`, ms serialization. |
| 7 | `punch_in` | `emp["shift_start"]` on unknown employee → TypeError → 500 instead of 404. Timestamp naive local; `date` from server calendar, not IST, no overnight rule (R1), no truncation. Any `status` accepted (incl. `ABSENT`). Seconds/float/string `punched_at` accepted. Check-then-insert race on `(emp_code, date)`. Returns non-contract `"id"` and raw datetimes instead of epoch ms. | Punch in for `EMP9999` → 500. `punched_at` as `"…"`, `1.5e12`, or seconds → 201. Two parallel punch-ins → 2× 201. | 404 first; strict epoch-ms validation (422); IST + overnight attendance date; status allow-list; atomic insert under unique `(emp_code, date)` index → 409; contract-shaped response. |
| 8 | `list_attendance` | `find(q)` loads the whole collection, sorts in Python (dies at ~100 k docs, ignores the required index); sort misses the `emp_code` tiebreak; `date_from > date_to` not rejected; returns `"id"` per doc; punch/history datetimes not converted to ms. | Same-date rows in arbitrary order; 100 k docs → seconds + RAM spike; `date_from > date_to` returns 200. | DB `sort(date −1, emp_code +1)` + `skip/limit`, filtered count, 422 on flipped range, full ms serialization. |
| 9 | Startup | No indexes are created at all (grader seeds only `_id`). | Every filtered/sorted query and every race guard degrades to collection scans / application-level checks. | `ensure_indexes()` at startup (idempotent) plus a cheap middleware re-check: unique `employees.emp_code`, unique `(emp_code, date)`, `(date −1, emp_code)`, `(emp_code, punch_in −1)`, `(department, emp_code)`. |
| 10 | Mongo client | `MongoClient(...)` without `tz_aware=True`, so BSON dates come back naive and every conversion silently assumes server-local time. | Same code gives different epoch values on servers in different timezones. | `tz_aware=True`; naive datetimes defensively treated as UTC. |
| 11 | Missing routes | `punch-out`, `regularize`, all four analytics and `explain` are `TODO` comments. | Any grader test touching them fails. | Implemented per `openapi.yaml`, analytics as aggregation pipelines (`$rank` for ties, `$densify` for the trend). |
| 12 | Input models | `EmployeeIn`/`PunchInIn` accept anything (bad email, `EMPabc`, `shift 25:99`, `LEAVE` punch-in) and crash or store it instead of 422. | `POST /employees` with `email: "x"` → 201. | Field patterns/lengths, `Literal`/Enum statuses, strict int epoch type, `shift_start != shift_end` validator; extra keys ignored so read-only derived fields can't be set. |

Also examined and found **not** defective: `load_dotenv()` without `override` (real env vars already win — correct); `HTTPException` error bodies (`{"detail": …}` matches the contract); `201` on the two create routes; `history: []` default on punch-in; `page_size` default of 20.
